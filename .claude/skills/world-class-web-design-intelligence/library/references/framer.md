## Strongest design qualities
1. **Product UI shown as live DOM, not screenshots.** The CMS, Collaborate and Analytics pages rebuild editor chrome in real HTML: collection lists with counts, field tables with Live/Draft statuses, branch lists with relative times, comment threads with reply counts. The CMS mock's date field showed **today's date** (10/19/2026) [measured]. Agent text is split into per-character spans for a typing reveal [measured]. **Why it works:** real text stays sharp at any pixel density, matches the page's type and theme, and can be animated part by part. A current date and believable data signal "this is the real product, today" more than a polished image does. **For SOCIA:** sociaos.com's product imagery could be rendered from SOCIA's own components with fixture data (the `zz-*` fixture-preview trick), so marketing never drifts from the app. Keep the data honest and labelled as an example.
2. **Hierarchy from size and text opacity, almost never weight.** Two families, about six sizes, weight 400 nearly everywhere; emphasis comes from white at 100/80/60/40% [measured]. **Why it works:** with weight held constant, every step in size or contrast reads clearly. Contrast steps are simple to apply consistently and survive theme changes. **For SOCIA:** this targets the baseline's known problems (eight weights from 500 to 800, ten sizes between 9 and 13.5px). SOCIA is denser, so a fair adaptation is 3 weights (400/600/700) and the existing primary/secondary/muted text tokens doing the work 650/750/780 do now. Change it system-wide, never page by page. **Confirmed and sharpened by the logged-in app:** the editor runs on six *named* size tokens (micro 9, caption 10, base 12, baseLarge 13, heading 16, display 20) and two weights (450 body, 550 emphasis) [measured]. 19 of 21 text nodes in the editor shell were 12px/450 [measured]. The app uses solid greys (`#fff`, `#ccc`, `#999`, `#777`, `#666`) rather than white opacities, but the principle is the same: contrast steps, not weight, carry hierarchy.
3. **The comparison row shows the winner without hiding the loser.** In the A/B mock, the winning variant's row is full white, the other is `#999`, a tiny 10/600 accent label marks the winner, and the baseline's lift cell is "—" [measured]. **Why it works:** contrast does the ranking before anyone reads a number; keeping the losing row visible preserves context; "—" says "not applicable" instead of a misleading 0%. **For SOCIA:** Trial Reels results, plan-loop outcomes and post comparisons in Analytics. It matches Noah's "unknown is — with a reason" rule.
4. **Ranked breakdowns with the bar inside the row.** The Analytics mock pairs a five-KPI row (12/500 label, 20/600 value) with Sources, Pages, Countries and Devices panels. Each panel is a list of 30px rows whose background is a white 8% bar sized to the value; a dimension switcher sits in the panel header; a 5px accent dot marks the live metric [measured]. **Why it works:** the bar lives where the eye already is (no separate chart to cross-reference), and one header control swaps the dimension without a new screen. **For SOCIA:** Analytics top posts, traffic sources, audience countries and devices. **But** the mock's bars aren't proportional (536K gets 442px, 88K gets 210px; linear would be about 72px) [measured]. SOCIA must scale linearly from zero.
5. **Usage is a control inside the plan, priced live.** Basic and Pro each carry a native `<select>` of monthly AI-credit tiers, and picking one updates the price at once (Basic went from CA$14 to CA$70 at 5,000 credits) [measured]. The compare table explains every row in one line under its label, puts overage pricing and caps inline (cost per extra unit plus a maximum), and groups rows into Limits, Agents, Live collaboration and Add-ons [observed]. **Why it works:** the person sizes the variable cost before checkout. A native select is keyboard- and phone-friendly for free. Inline overage terms answer "what happens if I exceed it?" in the row itself. **For SOCIA:** the cost model says Growth and Pro lose money at full AI use; a credit dimension per plan, shown this way, is one honest fix. It fits /pricing and Settings → Plan. **Correction from the logged-in app:** the in-app Plans page does *not* have the tier select; each plan lists a fixed monthly credit amount as one feature line [observed]. The live tier picker exists on the marketing page only, and usage is tracked separately in Settings → Usage (see the logged-in section).
6. **On phones, the compare table becomes one plan at a time.** Below 810px the table shows a single plan column with a sticky plan switcher (41px tabs plus the price) [measured]. **Why it works:** a 3–4 column matrix can't be read at 375px; one column plus a persistent switcher keeps rows full width and the context visible. **For SOCIA:** the pricing page and any plan-compare sheet on mobile.
7. **The AI is taught through concrete, copyable prompts organised by job.** The agents page opens with ten job tiles (anchor links). Each job is a section with a sticky description on the left and prompt groups on the right; each prompt has a copy button; a sticky icon rail scroll-spies the jobs [measured]. **Why it works:** recognition beats recall. Seeing real requests sets expectations about scope and phrasing better than any capability list does. **For SOCIA:** Settings → AI Assistants (the MCP connection), with example prompts per job ("plan my week", "compare platforms") and a copy button. The same idea works as starter prompts in Generate Caption's empty state.
8. **The agent narrates its work, then hands over alternatives.** The design-agent mock shows the prompt, a thinking state, a completed step with elapsed time ("Created a design plan · 2s"), then the result placed as **named explorations** side by side [observed]. The homepage prompt box has starter chips and a visible "Start without AI" path [observed]. **Why it works:** step-plus-time feedback makes the wait legible and auditable, named variants turn one answer into a choice, and the manual path keeps AI optional. **For SOCIA:** Make This Video, Plan These Posts and Generate Caption: show the real steps (for example "Read your last 30 posts") with timing, offer 2–3 labelled options, and always keep the manual composer one click away. **Caveat after the logged-in pass:** this is still the *marketing mock* of the agent. A real run was not observed (no prompt was sent), so step-with-timing and named explorations are unconfirmed in the product.
9. **Async-dependent chrome fades in once it's known.** An inline auth check decides between Log in/Sign up and the signed-in state; those buttons then appear with the 0.4s opacity spring [measured]. A signed-in visitor gets a "D" shortcut to the dashboard, and the projects page is pre-rendered via speculation rules [measured]. **Why it works:** nothing flashes the wrong state, and the returning user's next step is instant. **For SOCIA:** the top bar's plan badge, workspace switcher and connection status should reserve their space and fade in on resolution, not flash a default. sociaos.com could show "Open SOCIA" and pre-render /dashboard when a session exists.

## Best interactions
- **Focus equals hover.** Marketplace tiles lift -3px on keyboard focus through `:has(:focus-visible)`, the same feedback as pointer hover, at 0.14s ease-out [measured]. Keyboard users get the same signal.
- **Opacity-only appear for chrome.** Nav buttons fade without moving (0.4s spring with a 1.4% overshoot that's invisible on opacity) [measured]. Nothing jumps.
- **Off-screen animations pause** and replay when they come back into view [measured]. Motion costs nothing while unseen.
- **Live price recalculation** on credit-tier change [measured].
- **Forms survive early submits.** An inline script queues a submit made before JavaScript hydrates, and the prompt form carries hidden honeypot inputs [measured]. Fast typists don't lose input, and bots are filtered without a CAPTCHA.
- **Typewriter placeholder** in the prompt box (it was mid-word when sampled) [measured]. Decorative; see below.

## Best UX patterns

- **Inline plan economics:** viewers are free, editor seats are priced per editor, the overage rule (one grace month plus an email) sits in the FAQ, and each limit row carries its own overage terms [observed].

- **Status in the footer:** a quiet "All services online" indicator [observed].

## What makes it feel premium
- **Restraint:** pure black, one ramp of white opacities, and the accent almost absent from the chrome, so the product mocks carry the only colour [measured].
- **Size-scaled negative tracking** (about -0.04em on display, nearly 0 on body) and Inter character variants on figures [measured].
- **Physical motion with little bounce:** springs at bounce 0–0.2 instead of linear or default ease; opacity-only for chrome, movement only for content [measured].
- **Hairlines instead of shadows:** inset 1px white 8–10% borders and almost no drop shadows [measured].
- **Real, current data in the mocks** (today's date, believable counts and statuses) [measured].

## Weaknesses
- **Accessibility gaps on custom controls:** the billing toggle is a `div` with `tabindex` but no switch role or checked state; the mobile plan tabs have no tab roles; the copy-prompt buttons and the icon rail have no labels; the prompt's submit button (20×20) and the hamburger have no `aria-label` [measured]. The app repeats part of this: the editor's panel tabs (Pages / Layers / Assets, Agent / Style, Collections / Fields / Plugins) are plain buttons with no tab role or selected state, and the canvas tools are `div role=button` [measured]. Its menus, though, are proper `menu` / `listbox` / `option` elements with `aria-disabled` [measured].
- **Small touch targets:** hero CTAs are 29px tall on phones and the billing toggle is 20×12 [measured]. The hamburger is a good 64×64 [measured].
- **Prices swap after load:** server-rendered prices showed USD ($10/$30) and switched to CA$14/CA$41 after hydration [measured]. The likely result is a visible flash of the wrong price [inferred].
- **Mock data takes liberties:** the analytics bars aren't proportional to their values [measured].
- **Scroll-heavy pages:** the agents page runs about 19,000px of stacked sticky cards, and reveals replay on every pass [measured]. That's tiring to re-scan and makes the motion repetitive [inferred].
- **Weight-400 titles** scan weakly in dense lists [inferred]. That's fine on a marketing page, not in an app table.
- **Two visible systems:** framer.com (weight 400, radii 8/15/25, Framer runtime) and the marketplace (weight 450, its own token scale, its own header) [measured]. It's the same seam SOCIA has between sociaos.com and the app.
- **Consent mismatch:** the analytics product is sold on not needing cookie banners, while framer.com shows an Ok-only banner and loads about ten third-party tracking scripts on first view [measured from the script list].

### Measured app system
- **One density for the whole tool:** every control is 30px tall (panel tabs, buttons, inputs, menu rows, tool buttons) with an 8px radius [measured]. Panels are 260px on both sides and the top bar is 51px, exposed as CSS variables (`--framerInternalUI-propertyPanelWidth: 260px`, `chromeToolbarHeight: 51px`) [measured]. **Why it works:** one height means any control can sit next to any other without alignment work, and the eye reads rows as rhythm. **For SOCIA:** pick one control height for the app (SOCIA's dense UI suggests 30–32px) and make buttons, selects, inputs and segmented controls all match.
- **Concentric radii:** menu 13px = item 8px + 5px padding; floating toolbar 18px = tool 8px + 10px padding; prompt card 15px; command palette 15px with 10px rows; tooltip 10px; small chips and 20px icon buttons 5px [measured]. **Why it works:** inner and outer corners stay parallel, so nested surfaces look machined rather than stacked. **For SOCIA:** this is the rule the baseline asks for ("radius grows with element size"): outer radius = inner radius + padding.
- **Surface ladder by lightness, not shadow:** panels `#111`, canvas/editor background `#171717`, dashboard main `#1d1d1d`, selected tab / secondary button / input `#1f1f1f`, menus `#242424`, hover/highlight `#2b2b2b`, tooltip `#303030`; panel divider 1px `#212121` [measured]. Shadows are tiny (`0 3px 6px` at 8%) and always paired with a 1px ring (`#333` on menus, white 7% inset on floating surfaces) [measured]. **Why it works:** each step up in lightness means "closer to you", so elevation reads without blur. **For SOCIA:** SOCIA's dark theme can define its surfaces the same way (base, panel, raised, overlay, hover) instead of reusing one card colour.
- **Type:** see the corrected bullet under "Strongest design qualities" (six named sizes, weights 450/550). Page titles in Settings are 16/550; the dashboard heading is 20/550; nothing larger exists in the app [measured]. Numbers use `tabular-nums` (stepper values, usage figures, breakpoint widths) [measured].
- **Accent discipline:** `#09f` fills exactly one button per screen: **Publish** in the editor, **New project** on the dashboard [measured]. Subscribe, Invite, Add locale, Upgrade (in panels), Connect domain and Learn more are all the neutral `#1f1f1f` button [measured]. The only other accent use is "Upgrade now" as a 6% accent-tinted ghost button with accent text, weight 550 [measured]. **Why it works:** the accent always means "the consequential action here", so it never has to compete. **For SOCIA:** purple is already action-only; go further and allow one filled purple button per screen (Schedule / Publish / Connect), everything else neutral.
- **Icons:** 12px icons at stroke 1.5 in list and nav rows (`#888` inactive, white active), 20px icon boxes in toolbars, 8px chevrons on dropdowns, 12px check marks in plan lists [measured]. **For SOCIA:** close to SOCIA's 12–14px lucide sizes; the lesson is the fixed size *per context*, not the glyphs.

### Shell and navigation
- **What:** a single logo button labelled with the current view ("Canvas ▾") opens the main menu: a "Type to search…" field, then the five views (Canvas, CMS, Localization, Analytics, Settings) with ⌥1–⌥5, then Go to dashboard and Quick actions ⌘K, then the app menus (File, Edit, View, Tool, Layout, Text, Vector, Component, Plugins, Code, Preferences, Help) as hover submenus [observed]. **The current view is listed but disabled** (40% white), and menus that don't apply dim instead of disappearing: Text and Vector with nothing selected; Tool, Layout, Component and Code in Analytics [measured]. Submenus open aligned to their parent row and shift up to stay on screen [measured]. View toggles show a leading check [observed]; Preferences is a submenu of editor behaviour options (mostly on/off) rather than a settings page [observed; toggle states not read]. **Why it works:** the menu's shape never changes, so spatial memory holds; dimming tells you a command exists but needs context; the disabled current item doubles as a "you are here". **For SOCIA:** a command palette or "Go to" menu should keep a fixed order and dim unavailable items with a reason (for example "needs a connected account"), not hide them.
- **Top bar:** view menu and insert tools (each with a shortcut in its tooltip) on the left, project name with a small branch chip centred, collaborators / Preview / Invite / Publish on the right [observed]. **Left panel** tabs change per view (Pages / Layers / Assets on Canvas; Collections / Fields / Plugins in CMS; Locales / Plugins in Localization; a single nav list in Analytics and Settings) [observed]. **Why it works:** the frame stays put while the left panel's *content* changes with the job, so switching views never relocates the main controls. **For SOCIA:** sections like Content Studio or Analytics can keep one secondary panel whose tabs depend on the section, rather than each page inventing its own sub-navigation.
- **Floating canvas toolbar:** a 354×50 pill at the bottom centre (Select, Pan, Comment, Theme, a zoom dropdown, and "Upgrade now") [measured]. **Correction to the brief:** the "1%" next to "Upgrade now" is the **canvas zoom level**, not a usage meter [measured]. The upsell lives in the work surface permanently, which is a weakness (below).

### Agent panel (idle)
- **What:** the agent docks in the right panel and **stays available across Canvas, CMS and Analytics** [observed]. Top: a chat-history dropdown ("New chat" when empty) plus a new-chat button (⌘J per the shortcut table) [observed, measured from app code]. No starter chips were visible in the idle state [observed].
- **Context-aware composer:** on Canvas it sits under Agent / Style tabs and includes the Select tool; in CMS and Analytics the tabs and the Select tool disappear, and in Analytics the placeholder changes to an analytics question ("Ask about your site analytics…") [observed]. Elsewhere the product routes work to the agent from the page itself: the CMS empty state says to generate a collection with the Agent, and the Usage page's description ends in an "analyze your usage" button that names the Agent [observed; the button wasn't pressed]. **Why it works:** the AI's scope is stated by the placeholder before anyone types, and tools that can't apply aren't offered. **For SOCIA:** the AI entry point should name its scope per screen ("Ask about this week's results" on Analytics, "Ask about your schedule" on Calendar) and only offer context tools that work there.

### Menus, tooltips and the command menu
- **Menu anatomy:** 240px wide, `#242424`, 13px radius, 5px padding, 30px rows with 8px radius, 12/450 labels, shortcuts as separate glyphs in white 40%, three separators [measured]. **Motion:** opacity 0→1 and scale 0.96→1 from the anchor edge (transform-origin at the top centre) in **80ms** with `cubic-bezier(.21,.37,.49,1)` [measured]. **Why it works:** 80ms is below the threshold where a menu feels like it's "animating"; the scale from the anchor still tells you where it came from.
- **Tooltips** are 30px pills (`#303030`, 10px radius) with the label and, when one exists, a shortcut chip (10px `#999` on white 10%, 5px radius, inset hairline) [measured]. They rise 4px and scale from 0.96 in **150ms** with an expo-out curve `cubic-bezier(.16,1,.3,1)` [measured]. Toolbar icons, the composer tools and Preview all teach their shortcut this way [observed]. **For SOCIA:** every icon-only button gets a tooltip with its name, plus a shortcut chip where one exists.
- **Quick actions (⌘K):** a narrow 330px palette near the top centre (`#1f1f1f`, 15px radius) with a search field, grouped sections (Project, Plugins; 12/550 `#777` labels), 40px rows with 10px radius, the first row pre-highlighted (`#2b2b2b`, white) and the rest `#999`, shortcuts right-aligned in `#666` [measured]. Its default list is a short set of creation and project commands (new page, new component, new agent chat, publish, version history, invite) [observed]. **For SOCIA:** a ⌘K palette with Create (post, plan, video), Go to (sections), and Workspace (switch brand) groups; rows taller than menu rows because they carry icons and need a bigger hit area.
- **Hover transitions** are plain `ease` at 0.1–0.2s on colour and background, with no movement [measured]. The marketing site's springs don't appear in the app.

### Projects dashboard
- **What:** a 260px sidebar (workspace switcher, search, a Projects group with All / Archive / New folder…, and an "Invite your team" footer with Copy link) and a main area with a 20/550 heading, a sort dropdown (last viewed by me / last edited / alphabetical) and the accent "New project" button [observed]. Tiles sit in a centred grid of fixed 260px columns with 40px gaps; each is a **portrait 260×320 thumbnail** (10px radius, a flat skeleton while loading), then name 13px white, "Viewed … ago" 13px `#888`, and a small plan badge on the right [measured]. **On hover, the badge slot turns into a "…" menu button** [observed]. The workspace menu holds all workspaces, add/invite, Day mode, Settings (⇧,), Support and Sign out [observed]. **Why it works:** sort is by *your* last view, so the thing you were just in is first; the hover swap shows actions only when you're pointing at that item, without adding a column. **For SOCIA:** the brand/workspace list and Calendar post cards can swap a status chip for a "…" on hover (and keep the menu reachable by keyboard); default sort "last opened by me".

### Weaknesses seen in the app
- **Small targets in the most-used place:** the composer's Select / Add / Send buttons are 20×20 [measured]. Fine for a mouse, poor for touch and for accessibility.
- **Upsell in the work surface:** "Upgrade now" sits in the canvas toolbar beside the tools at all times [observed]. It competes with the work.
- **Empty-state text columns are very narrow** (116–177px), so short sentences break into three lines [measured].
- **Panel tabs aren't tabs** to assistive tech (no role, no selected state) [measured].
- **Menus rely on finishing their exit animation:** if the page stops drawing frames, a closed menu stays invisible but clickable [measured, hidden-pane edge case]. Setting `pointer-events: none` at the start of the exit would prevent it.

## Patterns NOT relevant to SOCIA
- **Giant display type** (54px Walsheim with -2.16px tracking) and full-black marketing theming: Noah's rules exclude giant type, and the app needs light and dark.
- **Bento feature grid** and **stacked sticky cards** across very long pages: bento grids are on Noah's do-not list, and long scroll-driven stories don't fit a dense working app.
- **Reveals that replay on every scroll pass,** the hero video with a grain overlay, customer-site marquees and the typewriter placeholder: decoration with no state meaning.
- **Duotone icon sprites and superellipse corners:** they'd break lucide consistency; `corner-shape` is a Chromium-only nicety.
- **A full-width mega-menu inside the app:** SOCIA's navigation is its sidebar.
- **The editor chrome itself** (canvas, layers, breakpoints, insert tools, a three-panel layout around a canvas): SOCIA isn't a design tool. Only the menu, tooltip, settings and empty-state lessons transfer.
- **A 12px base size for everything:** right for a desktop pro tool used for hours; SOCIA's creators also work on phones, so its body text should stay at 13px or above.
- **App menus behind the logo (File, Edit, View…):** a desktop-app convention for a tool with hundreds of commands. SOCIA's command count fits a ⌘K palette.
- **A permanent upsell in the work surface** (Upgrade now in the canvas toolbar): it competes with the work. SOCIA's upgrade prompts belong at the point of a limit, not in a toolbar.
- **20×20 icon buttons as the main AI controls:** too small for touch.
