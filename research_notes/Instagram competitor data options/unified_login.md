# Instagram API with Unified Login: can each SOCIA customer get Business Discovery and Hashtag Search without a Facebook Page?

Research date: 2026-11-01. All Meta pages were fetched as their published `.md` versions on this date (docs are at Graph API v26.0). "UNVERIFIED" means no primary source confirms it, or primary sources disagree.

Short answer: **partly confirmed, with one important contradiction.** Meta's docs say Unified Login works without a Facebook Page, accepts Instagram or Facebook credentials, is recommended for new integrations, and supports Hashtag Search. Business Discovery is a different story. Its guide page says it is "available with" Unified Login, but its endpoint reference still says "Available for the Instagram API with Facebook Login" and asks for a Facebook User token with `pages_read_engagement`. The overview's feature matrix doesn't list Business Discovery at all. A real test call is the only way to settle it, and SOCIA can run that test itself in Development mode, before any App Review.

## 1. What is "Instagram API with Unified Login", when was it introduced, and is it generally available?

### Takeaway
It is the third Instagram API setup. It sits on top of Facebook Login for Business: one login URL (`config_id`) where a client signs in with either Instagram or Facebook. The client picks a business portfolio and an Instagram account, and the app gets a Business Integration System User (BISU) token for `graph.facebook.com`. Meta calls it the recommended setup and says new features ship only there. The docs show no beta or partner-only label. There is no launch date in the changelog, but the docs describe it as recently launched.

### Cited Findings
- Meta lists three setups and says: "Instagram API with Unified Login is recommended for new integrations. App users can connect their Instagram professional account by logging in with either Instagram or Facebook, without a Facebook Page." — [Instagram Platform overview](https://developers.facebook.com/documentation/instagram-platform/overview)
- "The Instagram API with Unified Login is the recommended setup for new integrations. New Instagram API features are released only for this setup." — [Instagram API with Unified Login](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login)
- How it works, per Meta: (1) create a configuration in the App Dashboard and get a login URL; (2) put the URL on a button; (3) the client "logs in with Instagram or Facebook. They select their business portfolio, the Instagram account to share, and any additional assets"; (4) Meta redirects with a code that the server exchanges for a token; (5) the app "calls the API at `graph.facebook.com` with the access token and the client's Instagram account ID." — [Instagram API with Unified Login](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login)
- "The Instagram API with Unified Login is built on Facebook Login for Business." — [Authentication and access tokens](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login/authentication)
- Signs that it launched recently: the migration guide has a section titled "What isn't supported yet" that begins "At launch, the Instagram API with Unified Login doesn't support:" the Handover Protocol, switching a personal account to professional during login, logging in through the Instagram app, and the API integration helper. — [Migrate your App (Instagram Login → Unified Login)](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-instagram-login/migration-guide)
- "Newly created apps can't set up the Instagram API with Instagram Login." — [Migrate your App](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-instagram-login/migration-guide)
- Existing setups are not being retired yet: "This documentation does not announce a retirement date for existing Instagram API setups." — [Migrate to the Instagram API with Unified Login](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login/migration). Also: "Do you have to move now? No. Your existing integrations will continue to work. There is no end date yet." — [Migrate your App](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-instagram-login/migration-guide)
- The Instagram Platform changelog has no "Unified Login" entry. Its newest entry is dated July 30, 2026 (the `media_url` copyright/download change). — [Changelog for Instagram Platform](https://developers.facebook.com/documentation/instagram-platform/changelog)
- The Instagram Platform `llms.txt` index does not list any Unified Login pages yet. The pages exist and load as `.md`. — [llms.txt](https://developers.facebook.com/documentation/instagram-platform/llms.txt)
- Secondary: an open-source project's research issue dated October 27, 2026 already lists "Unified Login (no Page, business portfolio required, system-user token)". — [eukosh/social-kit issue #2](https://github.com/eukosh/social-kit/issues/2). Another project merged a switch to Unified Login on November 1, 2026, saying "Meta now recommends the Instagram API with Unified Login". It was "tested against fakes only, not a live sign-in yet." — [staqly PR #197](https://github.com/staqly/staqly/pull/197)

### Inferences
- The changelog doesn't mention it, `llms.txt` doesn't index it, the docs say "at launch", and third-party projects only started adopting it in late October 2026. Together these suggest it launched around September–October 2026. The exact date is UNVERIFIED.
- Nothing in the pages read calls it beta, limited or partner-only. Access is gated by app setup: the app must be owned by a business portfolio and use Facebook Login for Business (see question 6). Whether the "API setup with Unified login" tab already shows for every eligible app, or is rolling out gradually, is UNVERIFIED. Noah can check SOCIA's App Dashboard directly.

### Gaps
- No Meta blog post or changelog entry announcing the launch was found, so the exact introduction date is unknown.

## 2. Does it truly not require a Facebook Page? Which credentials does the end user use, and what does consent look like?

### Takeaway
Yes. Meta says plainly that no Facebook Page is required, and the client can log in with Instagram credentials alone. The real new requirement is a **business portfolio** (Meta Business Manager) on the client's side. Meta says every Instagram professional account already has one, and clients who log in with Facebook can create one during login. The consent flow is Meta-hosted: log in, pick a business portfolio, pick the Instagram account(s), pick optional extra assets, review permissions, return to the app.

### Cited Findings
- Overview comparison table: "Facebook Page: Not required"; "Business portfolio: Required"; "App user login: Instagram or Facebook credentials". — [Instagram Platform overview](https://developers.facebook.com/documentation/instagram-platform/overview)
- "The Instagram API with Unified Login and the Instagram API with Instagram Login can serve app users who don't have a Facebook Page." — [Instagram Platform overview](https://developers.facebook.com/documentation/instagram-platform/overview)
- Client requirements: "An Instagram professional account (Business or Creator). Personal accounts can't connect." and "A business portfolio. Every Instagram professional account already has one. Clients who log in with Facebook can also create one during login." — [Migrate your App](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-instagram-login/migration-guide)
- FAQ: "Do my clients need a Facebook account? No. Clients can log in with Instagram." — [Migrate your App](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-instagram-login/migration-guide)
- The screens a client sees: (1) Log in. "A client who is already logged in to Facebook continues as that account", and `prompt=login` makes both options always show. "Instagram login opens in the browser, not in the Instagram app, so your client needs their Instagram password." (2) Select a business portfolio. "The access token your app receives is scoped to this business portfolio." (3) Select the Instagram account; more than one is allowed. (4) Select additional assets such as an ad account, which can be skipped. (5) Review permissions, possibly with an ads disclaimer and an "Allow access to messages" toggle. (6) Return to the redirect URL. Meta also warns: "Many clients think of their business as just their Instagram account. Tell them before they start that they'll be asked to select a business portfolio." — [Business onboarding](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login/business-onboarding)
- The login URL is the Facebook Login for Business dialog: `https://www.facebook.com/dialog/oauth?client_id=…&config_id=…&redirect_uri=…&response_type=code&display=popup&prompt=login`. — [Get started](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login/get-started)
- Facebook Login for Business general requirement for BISU tokens: "Businesses onboarding to your app must have, or be willing to create, a business portfolio". — [Facebook Login for Business](https://developers.facebook.com/documentation/facebook-login/facebook-login-for-business)
- Troubleshooting: "The client can't see their Instagram account" can mean "It's a personal account, or it belongs to a different business portfolio". — [Eligibility and troubleshooting](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login/eligibility-and-troubleshooting)

### Inferences
- For SOCIA's typical customer (a small creator or café with only an Instagram account), the new friction is the business portfolio picker, not a Page. Meta's statement that "every Instagram professional account already has one" suggests Meta auto-creates or exposes a portfolio for Instagram-only accounts. That is UNVERIFIED in practice, and it's the most likely point where a real customer would get stuck.
- Customers who sign in to Instagram with "Continue with Facebook", or with no password set, need to know the password, since the Instagram login opens in a browser.

### Gaps
- No primary or secondary source shows what an Instagram-only user actually sees on the business portfolio step, for example whether Meta creates a portfolio silently or asks the user to create one.

## 3. Token type and API host

### Takeaway
The token is a Business Integration System User (BISU) access token. It belongs to the client's business portfolio, not to a person, and by default it can be set to never expire. All calls go to `graph.facebook.com`, with the Instagram account ID in the path. `/me` returns the system user, not the Instagram account.

### Cited Findings
- "Your app receives a Business Integration System User Access Token. The App Dashboard shows this as System-user access token (SUAT). This access token belongs to your client's business portfolio, not to the person who logged in. It keeps working if that person leaves the business, and it covers every asset your client shared with your app for the chosen business portfolio." — [Authentication and access tokens](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login/authentication)
- Code exchange: `GET https://graph.facebook.com/v26.0/oauth/access_token?client_id=…&client_secret=…&code=…`. "Use your Meta app ID and app secret, not your Instagram app ID and secret." — [Authentication and access tokens](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login/authentication)
- Expiry: "Whether the access token expires depends on your configuration." Tokens can be managed or refreshed with the BISU Token Management API, which uses the client business ID from `GET /me?fields=client_business_id`. — [Authentication and access tokens](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login/authentication). Facebook Login for Business: BISU tokens default "to never expire for the common offline server-to-server communication", and the management API has `set_token_expires_in_60_days` and needs the `business_management` permission. — [Facebook Login for Business](https://developers.facebook.com/documentation/facebook-login/facebook-login-for-business)
- "With this access token, `/me` returns the business integration system user, not the Instagram account. To get the Instagram account IDs, call `/me/assigned_instagram_accounts`." — [Authentication and access tokens](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login/authentication)
- Invalidation: the token stops working "if your client removes your app from their business portfolio or moves the Instagram account to another business portfolio." — [Authentication and access tokens](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login/authentication)
- The IG User reference requirements table lists, for Unified Login: Access token "Business Integration System User access token", host `graph.facebook.com`, login type "Facebook Login for Business", permission `instagram_basic`. — [IG User reference](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-user)
- Business portfolios: "If your client has Instagram accounts in more than one business portfolio … your app gets a separate access token for each." — [Business onboarding](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login/business-onboarding)

### Inferences
- A never-expiring per-customer token would remove SOCIA's 60-day Instagram token refresh job for these connections. Under SOCIA's security rules the token must still stay server-side only.

### Gaps
- None material.

## 4. Permissions and scopes, App Review, and whether Hashtag Search still needs "Instagram Public Content Access"

### Takeaway
Unified Login uses the Facebook Login `instagram_*` family (`instagram_basic`, `instagram_manage_insights`, and so on), not `instagram_business_*`. Each permission needs Advanced Access through App Review, and the app must be Live. Hashtag Search still needs the **Instagram Public Content Access** feature plus `instagram_basic`, and that feature is listed as supported by Facebook Login for Business. Business Discovery's reference page lists `instagram_basic`, `instagram_manage_insights` **and `pages_read_engagement`**. The last one is a Page permission, which is odd for a setup with no Page (see question 5).

### Cited Findings
- "The Instagram API with Unified Login uses Facebook Login for Business permissions. These are the `instagram_*` permissions, the same ones the Instagram API with Facebook Login uses, plus any other Facebook Login for Business permissions your integration needs." — [Permissions](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login/permissions)
- Meta's mapping from SOCIA's current permissions: `instagram_business_basic` → `instagram_basic`; `instagram_business_content_publish` → `instagram_content_publish`; `instagram_business_manage_comments` → `instagram_manage_comments`; `instagram_business_manage_insights` → `instagram_manage_insights`; `instagram_business_manage_messages` → `instagram_manage_messages`. — [Permissions](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login/permissions)
- Default configuration: "`instagram_basic` and `instagram_manage_messages` permissions, which are required, plus `instagram_manage_comments`, `instagram_content_publish`, `ads_management`, and `ads_read`". `instagram_manage_insights` and `instagram_manage_events` can be added with "Edit permissions". — [Get started](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login/get-started). Secondary: one adopter is unsure whether `instagram_manage_messages` can be removed ("Whether a configuration can leave it out is up to Meta's dashboard"). — [staqly PR #197](https://github.com/staqly/staqly/pull/197)
- App Review: "To connect clients who don't have a role on your app, your app needs Advanced Access to each permission, granted through App Review, and your app must be in Live mode. If your app already has Advanced Access to these permissions, for example from the Instagram API with Facebook Login, you don't need to request it again." — [Permissions](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login/permissions)
- Hashtag Search requirements: "you must undergo App Review and request approval for: the `Instagram Public Content Access` feature [and] the `instagram_basic` permission". — [Hashtag Search guide](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-facebook-login/hashtag-search). The same feature and permission appear on [IG Hashtag Search reference](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-hashtag-search), [recent_media](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-hashtag/recent-media) and [top_media](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-hashtag/top-media).
- Allowed uses of Instagram Public Content Access: "to discover content associated with your hashtag campaigns, understand public sentiment around your brand or identify contest, competition and sweepstakes entrants. It can also be used to provide customer support and better understand and manage your audience." — [Instagram Platform overview](https://developers.facebook.com/documentation/instagram-platform/overview)
- Facebook Login for Business "Supported features" includes "Instagram Public Content Access". Its permissions table marks `instagram_basic`, `instagram_manage_insights`, `pages_read_engagement` and `business_management` as available for BISU tokens. — [Facebook Login for Business](https://developers.facebook.com/documentation/facebook-login/facebook-login-for-business)
- Business Discovery reference permissions: "A Facebook User access token with the following permissions: `instagram_basic`, `instagram_manage_insights`, `pages_read_engagement`", plus `ads_management` or `ads_read` if the Page role came through Business Manager. — [IG User Business Discovery reference](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-user/business_discovery)
- The App Review page still describes only two login types and says "Your app can either use Facebook Login or Instagram Login but not both." Instagram Public Content Access appears only in its Facebook Login list. — [App Review for Instagram API](https://developers.facebook.com/documentation/instagram-platform/app-review)
- Secondary (conflicting view): one open-source research issue says hashtag search is "Out of reach under the bring-your-own-app model on any path" because of the Instagram Public Content Access review. That project's model differs from SOCIA's: each of its users brings their own Meta app. — [eukosh/social-kit issue #2](https://github.com/eukosh/social-kit/issues/2)

### Inferences
- SOCIA's existing Advanced Access is for the `instagram_business_*` family, so it would need a new App Review for `instagram_basic` and `instagram_manage_insights` (and `instagram_content_publish`, `instagram_manage_comments` if publishing and comments move too). It would also need the Instagram Public Content Access feature for hashtags. If SOCIA's Facebook connection already holds Advanced Access to any `instagram_*` permission, those carry over. Check **App Review > Permissions and features** in the dashboard.
- Instagram Public Content Access is a well-known hard review. Its allowed uses centre on a brand's own campaigns, sentiment and audience. "Trending in my niche" research for content ideas is close but not listed word for word. Approval is UNVERIFIED and should be treated as a risk.
- `pages_read_engagement` on Business Discovery is most likely a leftover from Page-linked docs that haven't been updated for Unified Login. But it may also be enforced. UNVERIFIED (see question 5).

### Gaps
- Meta's App Review page hasn't been updated for Unified Login, so it's unclear whether the submission flow or required screencasts differ.

## 5. Feature support matrix (Business Discovery, Hashtag Search, insights, publishing, comments, mentions, Audio API)

### Takeaway
Meta's overview table marks Unified Login as "Supported" for comment moderation, content publishing, **hashtag search**, insights, mentions, messaging, product tagging and partnership ads. **Business Discovery is not a row in that table.** It is claimed only on the Business Discovery guide page ("available with both … Facebook Login and … Unified Login"). The endpoint reference contradicts this ("Available for the Instagram API with Facebook Login", Facebook User token). The Audio API page says it is available with Unified Login, but its own "Before you start" still lists a Facebook Page and a User token. **Business Discovery under Unified Login is therefore UNVERIFIED until a live call succeeds.**

### Cited Findings
- Meta's table, Unified Login column, verbatim rows: "Comment moderation: Supported", "Content publishing: Supported", "Hashtag search: Supported" (Instagram Login: "Not supported"), "Insights: Supported", "Mentions: Supported", "Messaging: Supported", "Product tagging: Supported" (Instagram Login: "Not supported"), "Partnership ads: Supported" (Instagram Login: "Not supported"). The table has **no Business Discovery row and no Audio row**. — [Instagram Platform overview](https://developers.facebook.com/documentation/instagram-platform/overview)
- "The Instagram API with Unified Login supports comment moderation, content publishing, hashtag search, insights, mentions, messaging, product tagging, and partnership ads." Business Discovery is not named. — [Permissions, Feature support](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login/permissions)
- Business Discovery guide: "This API is available with both the Instagram API with Facebook Login and the Instagram API with Unified Login." It returns other professional accounts' `followers_count` and `media_count`, plus `media{comments_count,like_count,view_count}`. "`view_count` includes both paid and organic metrics"; "Data about age-gated Instagram professional accounts will not be returned." — [Business Discovery guide](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-facebook-login/business-discovery)
- Business Discovery reference (contradicts the guide): "Available for the Instagram API with Facebook Login." Permissions: "A Facebook User access token with … `instagram_basic`, `instagram_manage_insights`, `pages_read_engagement`". — [IG User Business Discovery reference](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-user/business_discovery)
- Hashtag Search guide: "This API is available with both the Instagram API with Facebook Login and the Instagram API with Unified Login." — [Hashtag Search guide](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-facebook-login/hashtag-search). Its reference pages still say "Available for the Instagram API with Facebook Login" and want "A User access token of a Facebook User who has been approved for tasks on the connected Facebook Page". — [IG Hashtag Search reference](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-hashtag-search). Here the overview table backs the guide, so hashtag support under Unified Login is better supported than Business Discovery.
- Audio API: "This API is available on the Instagram API with Facebook Login and the Instagram API with Unified Login. It is not supported on the Instagram API with Instagram Login." "If a search query is omitted, trending original sounds or music are returned by default." (`GET /ig_audio?audio_type={music|original_sound}&user_id=…`). The same page's "Before You Start" lists "A Facebook Page connected to that account" and "A valid User access token" with `instagram_basic` and `instagram_content_publish`. — [Instagram Audio API](https://developers.facebook.com/documentation/instagram-platform/content-publishing/audio-api)
- Not everything Facebook Login offers is available here: `collaborative_media` and `collaborative_media_search` are "Available for Instagram API with Facebook Login only"; `story_insights` webhooks are "Only available for Instagram API with Facebook Login." — [IG User reference](https://developers.facebook.com/documentation/instagram-platform/instagram-graph-api/reference/ig-user); [Insights](https://developers.facebook.com/documentation/instagram-platform/insights). The Story `link_clicks` metric is "Only available in Instagram API with Facebook Login." — [Changelog, June 22, 2026](https://developers.facebook.com/documentation/instagram-platform/changelog)
- Since July 30, 2026, `media_url` is left out of responses for other users' videos with licensed audio or with downloads turned off. This applies to `business_discovery{media}`, `top_media` and `recent_media`. — [Changelog, July 30, 2026](https://developers.facebook.com/documentation/instagram-platform/changelog)

### Inferences
- The pattern across pages is consistent: guide pages and the overview were updated for Unified Login, while reference pages and older "Before you start" boxes were not. On that reading, Business Discovery probably works, since Meta's guide says so and the endpoint is just a field on the IG User node, which does list the BISU token. But it is the one feature SOCIA needs most, and the matrix leaves it out. Treat it as **likely but UNVERIFIED** until tested.
- If it works, the SOCIA plan in the brief holds: each customer's own token runs `business_discovery.username(x){followers_count,media_count,media{like_count,comments_count,view_count,timestamp,permalink,caption}}`, so no central research account is needed. Audio API (trending audio) would come along too, which SOCIA lacks today.
- Insights may not match exactly. Media and account insights are "Supported", but some Facebook-Login-only items (story `link_clicks`, story_insights webhooks, collaborative media, which SOCIA's PR #54 reads) may not be available. Check each SOCIA call before migrating.

### Gaps
- No Meta source or developer report confirms a successful `business_discovery` or `ig_hashtag_search` call with a BISU token on an account with no Page.

## 6. Can an app on Instagram Login migrate users or run both? Setup requirements

### Takeaway
Yes. Meta has a step-by-step migration guide written for Instagram Login apps. SOCIA keeps its existing Meta app and runs both setups side by side while customers reconnect. Every customer must reconnect once, because Instagram User tokens don't work with Unified Login. App-side requirements: the app must be owned by a business portfolio, must use **Facebook Login for Business** (not classic Facebook Login), needs a configuration (`config_id`) with an HTTPS redirect, needs webhooks on the Meta app's Instagram object, and needs App Review for the `instagram_*` permissions. On the customer's side, the only setup is a business portfolio, which Meta says Instagram professional accounts already have.

### Cited Findings
- "Your existing Meta app. You don't need a new app." and "A business portfolio that owns the app. The API setup with Unified login tab only appears for apps owned by a business portfolio". — [Migrate your App](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-instagram-login/migration-guide)
- "An app that uses Facebook Login for Business … the API setup with Unified login tab only appears for apps that use it … If your app still uses Facebook Login, switch your app to Facebook Login for Business or create a new app." The app also needs the "Manage messaging & content on Instagram" use case. Dashboard path: Use cases > Manage messaging & content on Instagram > Customize > API setup with Unified login. — [Get started](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login/get-started)
- An existing Facebook Login for Business configuration can be reused if it has the "Instagram Login Compatible" label, meaning it "uses a Business Integration System User Access Token and requests only an Instagram account, or only an Instagram account and an ad account." — [Migrate your App](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-instagram-login/migration-guide)
- Reconnection is required: "Instagram User access tokens don't work with the Instagram API with Unified Login, so each client must connect again once." The rollout plan: keep the old token, send the new login link, fetch account IDs, subscribe webhooks, make one test call, then switch over. "While a client is connected both ways, you can receive messaging webhooks twice". — [Migrate your App](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-instagram-login/migration-guide)
- "Do I need to keep both integrations? Only while you move clients." — [Migrate your App](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-instagram-login/migration-guide)
- Code changes: host `graph.instagram.com` → `graph.facebook.com`; `/me` → explicit IG user ID; Meta app ID and secret instead of Instagram app ID and secret; webhooks move to "the callback URL set for the Instagram object on your Meta app" and subscribe via `POST graph.facebook.com/{ig-user-id}/subscribed_apps`; "Message IDs use a different format". — [Migrate your App](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-instagram-login/migration-guide)
- Testing in Development mode: invite your own Instagram professional account as an "Instagram Tester" (up to 50), accept it at Instagram web Settings > Website permissions > Apps and websites > Tester Invites, then "Generate token". "Test users aren't supported." — [Migrate your App](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-instagram-login/migration-guide); [Get started](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-unified-login/get-started)
- Facebook Login for Business BISU flow: "Your app can only request logins from web surfaces", and the app's business portfolio "needs to be separate from the business portfolio owned by your business client." — [Facebook Login for Business](https://developers.facebook.com/documentation/facebook-login/facebook-login-for-business)
- Conflicting older statement: "Your app can either use Facebook Login or Instagram Login but not both." — [App Review for Instagram API](https://developers.facebook.com/documentation/instagram-platform/app-review). The newer migration guide says running both during migration is expected.

### Inferences
- The concrete SOCIA checklist: (1) confirm the SOCIA app is owned by the SOCIA LLC business portfolio. It probably is, since the app is Business-Verified. (2) Check whether SOCIA's Facebook connection uses classic Facebook Login. If so, it must switch to Facebook Login for Business, which may affect the existing Facebook Pages integration. UNVERIFIED impact. (3) Create a Unified Login configuration with `instagram_basic`, `instagram_manage_insights` (plus publish and comments if moving everything). Ask whether `instagram_manage_messages` can be dropped, since SOCIA doesn't do DMs. (4) Test Business Discovery and Hashtag Search with a Development-mode token for the @salvoshermitage test account. (5) Only if those calls work, submit App Review including Instagram Public Content Access.
- A narrower option: keep Instagram Login for everything that works today, and add Unified Login as an optional "Unlock competitor research" connection. The migration guide's "run both" model allows this. Whether Meta treats one customer holding two connections as fine long-term is UNVERIFIED. The guide frames dual connections as temporary.

### Gaps
- Whether the dashboard demands `instagram_manage_messages` in every Unified Login configuration (Meta calls it "required" in the default configuration) is unclear. If so, App Review must justify a messaging permission SOCIA doesn't use.

## 7. Rate limits for Business Discovery and Hashtag Search under Unified Login

### Takeaway
Business Discovery and Hashtag Search fall under Graph API **Platform Rate Limits**, not the Instagram 4800 × impressions formula. Meta publishes no numeric per-user-token value. Hashtag Search has a hard cap of 30 unique hashtags per Instagram account per rolling 7 days. Meta doesn't say whether a BISU token counts as a "user" for Platform Rate Limits.

### Cited Findings
- "Business Discovery and Hashtag Search API are subject to Platform Rate Limits." Other Instagram calls use Business Use Case limits: "Calls within 24 hours = 4800 * Number of Impressions", counted per "app and app user pair". — [Graph API rate limiting](https://developers.facebook.com/docs/graph-api/overview/rate-limiting)
- Platform Rate Limits: app tokens "Calls within one hour = 200 * Number of Users"; for user tokens, "A user's call count is the number of calls a user can make during a rolling one hour window", and no number is published. — [Graph API rate limiting](https://developers.facebook.com/docs/graph-api/overview/rate-limiting)
- On system users, the rate-limit page only says (for Pages) that "requests made with system user or page access tokens are subject to Business Use Case Rate Limits". There's no statement about Instagram BISU tokens. — [Graph API rate limiting](https://developers.facebook.com/docs/graph-api/overview/rate-limiting)
- Hashtag cap: "You can query a maximum of 30 unique hashtags on behalf of an Instagram Business or Creator Account within a rolling, 7 day period." Requests to `recent_media` and `top_media` "count against the 30 hashtag limit, even when you already have the hashtag's ID". — [Hashtag Search guide](https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-facebook-login/hashtag-search)

### Inferences
- With each customer's own token, both the 30-hashtag cap and the hourly Platform limit apply per customer account, not to SOCIA as a whole. That's far roomier than one central research account. SOCIA should read the `X-App-Usage` / `X-Business-Use-Case-Usage` headers in practice to see which bucket BISU calls land in. UNVERIFIED.

### Gaps
- No numeric hourly limit for Business Discovery per token. Meta doesn't disclose one, and no reliable secondary figure was found.
