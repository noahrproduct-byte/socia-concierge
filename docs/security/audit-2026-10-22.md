# SOCIA security audit and hardening, 2026-10-22

Scope: the whole repository at `main` (1eb4945), plus this branch's fixes. Seven independent reviews covered authentication and social OAuth, the database and storage policies, the content and team API routes, the remaining API routes and AI features, Stripe and entitlements, the MCP and OAuth server, and frontend, configuration and dead code. Every finding below was checked against the code before it was fixed.

**Status words.**
- **FIXED:** the code or SQL changed, and a test or a build proves the change.
- **VERIFIED:** checked and found correct, no change needed.
- **PARTIAL:** mitigated, not fully removed.
- **NOT FIXED:** left as is, with the reason.
- **MANUAL:** needs an action in a dashboard, outside the code.

Nothing here was tested against production or against real platform accounts.

## 1. Overall assessment

Before this pass, SOCIA was **not** safe for paying customers. One flaw was critical: anyone with the public key could list every customer's uploaded files. Four flaw types allowed cross-customer or cross-workspace harm:
- a destination planted on another customer's post;
- OAuth account injection on Instagram and Facebook;
- Members publishing as the brand;
- server-side request forgery (SSRF).

After this branch **and** the SQL migration, those are closed and covered by tests. Four risks remain open (section 11): the YouTube token sent to the browser, platform tokens readable by their own owner's browser, Studio and collaborator workspace scoping, and a CSP that is still report-only. SOCIA is not "completely secure". It is materially safer, with the remaining risks listed.

## 2. Findings and status

### Critical

**C1. Anyone could list every customer's media.** FIXED in SQL.
- Where: `supabase/schema.sql` ("Scheduled media: public read").
- The storage select policy is now owner-folder only, and the bucket accepts only image, video and audio types. Public URLs keep working.

**Next.js remote code execution and denial of service (6 advisories).** FIXED.
- Where: `package.json`.
- Next 15.5.23 was upgraded to 15.5.28, and PostCSS is overridden to 8.5.31. `npm audit --omit=dev` reports 0, and the production build passes.

### High

**H1. Instagram and Facebook connect had no OAuth state.** FIXED, with a test.
- Where: `app/api/auth/{instagram,facebook}/{start,callback}`, new `lib/oauthState.ts`.
- An attacker's code could attach their account to a victim's workspace, so the victim's posts would publish there. There is now a nonce in an HttpOnly cookie, checked in constant time before any code exchange.

**H2. A destination could be attached to someone else's post.** FIXED.
- Where: `supabase/post-destinations.sql`, `lib/publishing/runner.ts`, `lib/publishing/db.ts`.
- The publisher then published the victim's content and rewrote their post. Policies now require owning the parent post. The publisher loads the post as the destination's owner, and `refreshParent` and `loadItem` ignore foreign destination rows.

**H3. Members could send public comment replies as the brand.** FIXED, with a test.
- Where: `app/api/comments/act`, `lib/commentDrafts.ts`, `lib/comments.ts`.
- Send and skip are now owner or admin only. Drafts are scoped to the workspace, and Facebook replies use that workspace's Page.

**H4. Full-response SSRF through Studio audio media.** FIXED, with a test.
- Where: `app/api/studio/audio/media`, new `lib/fetchGuard.ts`.
- Only https on the Instagram and Facebook CDNs is fetched, and every redirect hop is re-checked.

**H5. SSRF through repurpose, with the result stored publicly.** FIXED.
- Where: `app/api/repurpose`.
- SOCIA's own files are read from storage by a checked path, and the stored URL is never fetched.

**H6. Members could rewrite or delete scheduled or approval-pending posts, bypassing approval.** FIXED, with a test.
- Where: `app/api/schedule`, `app/api/posts/[id]`.
- Members get a 409. Create post items can only be cancelled there, and cancelling now cancels their destinations.

**H7. Every Page token sat in a row the owner's browser could read.** FIXED.
- Where: `app/api/auth/facebook/{callback,select}`, new `lib/facebookPending.ts`.
- An agency Admin connecting would leak tokens for all their client Pages. Tokens now live in a server-only table, and existing pending lists are scrubbed by SQL.

**H8. A cancelled Pro trial kept Pro-sized resources on Free.** FIXED, with a test.
- Where: `app/api/stripe/webhook`, new `lib/planDowngrade.ts`, `lib/context.ts`.
- After any subscription change, whatever exceeds the plan is paused (never deleted), as the privacy policy already promised. Invited people lose access when the owner's plan no longer includes a team.

**H9. The browser could insert workspaces and connection rows, bypassing plan caps.** FIXED.
- Where: `supabase/security-hardening.sql` triggers, the connect callbacks.
- Connection rows are written only by the server role. Only the first workspace may be created from a browser session. Row workspace ids must belong to the caller.

**H10. The owner's YouTube access token is sent to the browser for uploads.** NOT FIXED.
- Where: `lib/publishing/adapters/youtube.ts:241`, `lib/publishing/youtubeUpload.ts`.
- Removing it needs one real upload test: does YouTube accept chunk uploads to the session URI without the token? If not, the bytes must move through the server. Neither change can be made safely without a live test. See section 11.

### Medium

**M1. Open redirect on `/login?next=/.//evil.com`.** FIXED, with a test. (`lib/safeNext.ts`)

**M2. Open redirect through malformed OAuth authorize requests.** FIXED, with a test.
- Where: `lib/oauth/server.ts`. Errors now show SOCIA's own page.

**M3. Anonymous traffic could make SOCIA fetch any URL and store app records.** FIXED.
- Where: `app/oauth/authorize`. Sign-in now comes first, with 20 per minute per person.

**M4. `/oauth/revoke` had no limit and wrote audit spam.** FIXED.
- 60 per minute per address. A 4 KB body cap. An audit row only for a real token, and audit client ids are capped.

**M5. Assistant `create_post` could fill storage, and leave orphans past the deadline.** FIXED, with a test.
- Where: `lib/api/write.ts`. 250 MB from links per post, and no new link inside the last 30 seconds.

**M6. Competitor research had no limit and could exhaust the shared YouTube quota for everyone.** FIXED.
- Where: `app/api/competitors/intel`. 6 runs per hour per account (atomic).

**M7. Unbounded text in AI prompts.** FIXED.
- Where: `app/api/ask`, `app/api/profile`, `app/api/niche/analyze`.
- Context JSON is capped at 24 KB and deep-clipped. Profile brand fields and the niche post fields are bounded.

**M8. Guest syncs and reads used the owner's active brand.** FIXED.
- Where: `app/api/{instagram,facebook}/sync`, `publishing/youtube/options`, `publishing/tiktok/creator`, `lib/facebookSync.ts`, `lib/tiktokData.ts`.
- They now use the viewed workspace, and manual syncs are limited to 30 per hour.

**M9. Post ids were checked against the owner only, not the workspace.** FIXED.
- Where: `lib/publishing/db.ts` `loadItem`, and every route that loads a post.

**M10. Studio file paths were user-writable, then signed and deleted with the service role.** FIXED, with a test.
- Where: `lib/studioClips/storage.ts`, `server.ts`, `job.ts`, `jobs/studio-purge`.
- Paths must sit in the clip row's own folder.

**M11. Transcription length could be bypassed with compressed audio.** FIXED, with a test.
- Where: `app/api/studio/transcribe`, `lib/transcribe/limits.ts`. The WAV header must be 16 kHz mono 16-bit, and an unknown size is refused.

**M12. Video-build refunds could be claimed repeatedly, and a draft could be saved without a counted export.** FIXED, with a test.
- Where: `app/api/studio/builds/[id]/{export,draft}`, new `exportToken.ts`.
- The export path is signed. A refund happens once per path and never after the video was kept.

**M13. A removed Admin could rejoin with a kept invite, and Admins could mint Admin invites.** FIXED, with a test.
- Where: `lib/team.ts`, `app/api/team`, `TeamManager.tsx`.

**M14. Stale or out-of-order Stripe events, and duplicate checkouts.** FIXED.
- Where: `app/api/stripe/webhook`, `app/api/billing/checkout`.
- The live subscription is applied, never the event snapshot. An event for another subscription does not overwrite a live one. Checkout checks Stripe for existing subscriptions, and the trial goes only to new customers.

**M15. Re-running `plans-and-usage.sql` would revert security fixes.** FIXED.
- Banners mark it and `tiktok-connections.sql` as do-not-run.

**M16. Anyone could call the `socia_rate_hit` function and lock users out of features.** FIXED in SQL.

**M17. Guest Ask conversations were saved into the owner's history across brands.** FIXED.
- Where: `app/api/ask`. Chats are now the viewer's own. The unused `/api/conversations` route is removed.

**M18. A database blip on disconnect could delete every brand's connection.** FIXED.
- Where: the four disconnect routes. They widen the delete only when the workspace column is missing.

**M19. Platform tokens are readable from the owner's own browser session.** PARTIAL.
- Through the database's REST interface, the owner's own session can read the token columns. Writes are now blocked. Reads remain, because token reads go through the session client in many places. See section 11.

### Low

**FIXED:**
- **L1.** IPv6 spellings of internal addresses (`::ffff:7f00:1`, NAT64, 6to4) passed the private-address filter. Fixed with a test.
- **L2.** The MCP tools had no flat limit per connection before workspace lookups. Now 120 per minute.
- **L3.** Self-registered apps were not marked "Unverified" on the consent screen.
- **L4.** A Meta signed_request could be replayed indefinitely. Now refused after 7 days, with a test.
- **L5.** Cron secrets were compared in non-constant time. Fixed with a test.
- **L6.** CSV exports were open to formula injection. Fixed with a test.
- **L7.** Research links accepted look-alike hosts. Fixed with a test.
- **L8.** The events route had no limit. Now 300 per hour.
- **L9.** The legacy publisher ignored paused accounts.
- **L10.** Owners could rewrite which person a member row is (SQL column grant).
- **L11.** Members could rewrite alert text (SQL column grant).
- **L12.** Niche caches failed policy checks for second brands.
- **L13.** `..` was accepted in storage paths.
- **L14.** Responses sent `X-Powered-By`.
- **L15.** Session cookies were not marked Secure.

**PARTIAL:**
- **L16.** Content Security Policy. The safe directives are enforced. The full policy is report-only; with it, the production build showed 0 violations on the public pages.
- **L17.** Raw database error text reached the client. Removed in the touched routes; others remain.

**NOT FIXED** (low, in section 11): YouTube connect PKCE, revoking the grant at Meta on disconnect, gated analytics data in the page payload, state-changing GET routes, a `server-only` import guard, an orphan sweep for assistant imports, Admins reading invite tokens over REST.

## 3. Unused code removed

These have no caller anywhere: app code, database cron jobs, middleware or MCP. Each was checked by search before removal.
- `app/api/rate` and `app/dashboard/rate`: the old content rater, with no inbound link. Its prompt fields were unbounded.
- `app/api/conversations`: its caller was removed on 2026-09-07. It allowed unlimited writes into the owner's chats.
- `app/api/competitors/instagram`: its caller was removed on 2026-09-07. It read competitors pooled across brands.
- `app/api/comments/diagnose`: a debug route with no caller and no admin gate.

## 4. Intentionally preserved

These are called from outside the app, and each now has its own check:
- the OAuth callbacks;
- the Stripe webhook;
- the Meta deauthorize and data-deletion callbacks;
- the cron routes (`schedule/publish`, `sync/daily`, `jobs/weekly-plan`, `jobs/studio-purge`);
- `/mcp`, `/.well-known/*`, and the `/oauth/*` endpoints.

The admin-email-gated diagnostics (`instagram/inspect`, `instagram/daily-probe`, `dashboard-audit`) were kept. `/api/posts/[id]/publish` and `/api/publishing/accounts` were kept as documented contract endpoints. The unused UI files (`components/ui/*`, `FaqAccordion`, `UzFaq`, `SparkLive`, `RangeSelect`, `lib/demoData.ts`) carry no security risk and were left for a separate cleanup.

## 5. Dependencies

- `next` 15.5.23 to 15.5.28. `eslint-config-next` was moved to the matching version.
- `postcss` is overridden to 8.5.31 inside Next.
- `shadcn` moved to devDependencies. It is a build-time CSS import only.

## 6. Tests

New tests:
- `lib/security.test.ts`: every new guard.
- `app/api/security.routes.test.ts`: the handlers of every route file in the app, called with no session. Every one refuses or answers an empty or public result. The cron routes return 401, the webhooks 400 or 503, and forged-code connect callbacks redirect with an error before any exchange.
- `app/api/security.roles.test.ts`: Member and Admin refusals.
- `lib/planDowngrade.test.ts`.
- Additions to the MCP, OAuth, Meta signature, assistant-write and safe-redirect tests.

Results: 778 tests pass, `tsc` is clean, `eslint` is clean on every changed file, and `next build` passes.

The production build was also run locally. The homepage, sign-in, pricing and privacy pages rendered with 0 policy violations and 0 console errors.

Not tested: anything signed in against a real database, any SQL against Supabase, and any live platform call. The new SQL was not run.

## 7. Required manual steps (in order)

1. Deploy this branch.
2. Run `supabase/security-hardening.sql` in the Supabase SQL editor. It is idempotent. Until it runs, the critical storage listing and the browser-write gaps stay open in production.
3. Confirm with the anon key in a browser console: `supabase.storage.from('scheduled-media').list('')` returns `[]`, and `has_function_privilege('anon','public.socia_rate_hit(text,integer,integer)','execute')` is false.
4. Supabase Auth settings:
   - turn on "Secure password change";
   - set the minimum password length to 8;
   - confirm unconfirmed email identities are not auto-linked to Google sign-in.
5. In the Meta app, turn on "Require App Secret" so a leaked Meta token is useless without `appsecret_proof`. That also needs a small code change, so do it together with step 6 of section 11.
6. Stripe Dashboard: after failed retries, the subscription should end as canceled or unpaid, not stay past_due.
7. Keep `NEXT_PUBLIC_APP_URL`, `CRON_SECRET` and `SUPABASE_SERVICE_ROLE_KEY` set in Vercel. Connecting accounts now needs the service key.
8. Consider moving `CRON_SECRET` in the pg_cron jobs into Supabase Vault.

## 10. Breaking changes

- Members can no longer send or skip comment replies, or edit, cancel or delete scheduled posts through the calendar.
- Admins can no longer create Admin invites.
- Malformed AI-app authorize requests show an error page instead of redirecting.
- A Studio export saved by an older open tab (an unsigned path) is refused once; reloading fixes it.
- Transcription refuses audio that isn't the browser's WAV format, which every current code path produces.
- After a downgrade, items over the limit are paused automatically. The person can change which ones in Settings.

## 11. Remaining risks and the recommended next steps

1. **YouTube token in the browser (High).** Test one upload to the session URI without the Authorization header. If YouTube accepts it, drop the token from the response. If not, relay the chunks through a server route that adds the token.
2. **Owner-readable platform tokens (Medium).** Route every token read and write through the server role, then revoke select on the token columns from `authenticated`. This touches many readers, so it needs its own pull request and a real-database test.
3. **Studio builds, clips and collaborators are not workspace-scoped (Medium).** This affects cross-workspace Admins. `loadBuildRow`, `completeClip` and `deleteClip` filter by owner only, and the collaborators route doesn't check the account against the workspace.
4. **Enforce the CSP** once the signed-in pages show no reports.
5. **The low items** listed under "NOT FIXED" in section 2.
